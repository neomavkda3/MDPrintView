# Contributing to MDPrintView

Thanks for considering a contribution. MDPrintView is a solo-dev project — issues, well-scoped PRs, and ideas are all welcome.

## Before you open a PR

1. **Open an issue first** for non-trivial changes so we can align on direction before you sink time into it.
2. **Tests are required** for behavior changes. Swift Testing (the `Testing` framework, not legacy XCTest) is the convention.
3. **No new dependencies without discussion.** Bundle size and supply-chain surface area matter — see `docs/plans/2026-06-06-vendored-assets.md` for the current third-party JS list.
4. **Conventional-ish commits.** `feat:` / `fix:` / `refactor:` / `docs:` / `chore:` prefix the subject; one-line summary, then a paragraph if the *why* isn't obvious.

## Build setup

```sh
brew install xcodegen
git clone https://github.com/neomavkda3/MDPrintView.git
cd MDPrintView
xcodegen generate
xcodebuild -project MDPrintView.xcodeproj -scheme MDPrintView -configuration Debug build
```

Run with the helper script:

```sh
./scripts/run.sh                    # launch the Debug build, welcome window
./scripts/run.sh path/to/file.md    # launch and open a file
./scripts/run.sh --logs             # attached run — print() output streams to terminal
```

Tests + smoke:

```sh
xcodebuild -project MDPrintView.xcodeproj -scheme MDPrintView \
    -destination 'platform=macOS' -configuration Debug test
./scripts/smoke.sh
```

## Build system gotchas

- **`project.yml` is the source of truth.** `MDPrintView.xcodeproj` is regenerated by XcodeGen. Don't hand-edit `project.pbxproj` — changes vanish on the next `xcodegen generate`.
- **Debug builds intentionally omit App Sandbox.** They use `MDPrintView/MDPrintView-debug.entitlements` (empty plist). On macOS 26, ad-hoc-signed sandboxed apps fail to spawn WKWebView's WebContent helper, leaving the preview pane empty.
- **Release builds (OSS) are also non-sandboxed.** Developer-ID-signed distribution doesn't require sandbox; Sparkle works without the XPC service complexity. A separate Release-MAS configuration (sandbox + no Sparkle) will be added when the MAS SKU ships.
- **No network entitlement, ever.** Mermaid + KaTeX are bundled as local JS/CSS. CSP enforces no remote loads.

## Releasing (maintainer-only)

Releases are automated via GitHub Actions on tag push. See [`docs/RELEASING.md`](docs/RELEASING.md) (added alongside the CI workflow).

### Sparkle EdDSA key — first-time setup

The private signing key is generated once on the maintainer's machine and stored in:

1. The macOS login Keychain (Sparkle's `generate_keys` puts it there)
2. A backup in 1Password (`Sparkle/bin/sign_update --export-key` exports the private key for backup)
3. GitHub Actions secret `SPARKLE_ED_PRIVATE_KEY` for CI signing of releases

The matching **public** key lives in `MDPrintView/Info.plist` as `SUPublicEDKey` and is committed to the repo.

To generate the keypair the first time:

```sh
# After `xcodegen generate` resolves the Sparkle SPM artifact:
SPARKLE_BIN=$(find ~/Library/Developer/Xcode/DerivedData/MDPrintView-*/SourcePackages/artifacts -name 'generate_keys' -type f | head -1)
"$SPARKLE_BIN"
# Prints the public key. Embed it as <key>SUPublicEDKey</key>...<string>...</string> in Info.plist.
```

The private key never leaves the maintainer's machine + 1Password + the GitHub Actions secret. **Do not commit it.**
