# MDPrintView

Native macOS markdown editor + viewer with print-quality typography. Three pane modes (editor only, split, preview only), four reading themes, Mermaid diagrams, LaTeX math, and a print pipeline that keeps headings/code blocks/tables together across page breaks.

**Status:** v1.0 feature-complete in Debug. App Store submission gated on user-driven steps (Apple Developer enrollment, icon artwork, screenshots, ASC listing). See [`docs/STATUS.md`](docs/STATUS.md).

**Target:** macOS 26.0+ only. **Distribution:** Mac App Store (free, no IAP in v1).

## Quick start

```sh
# One-time
brew install xcodegen                       # project file generator

# Clone, generate Xcode project, build, run
git clone <repo>
cd MDPrintView
xcodegen generate
xcodebuild -project MDPrintView.xcodeproj -scheme MDPrintView -configuration Debug build

# Launch the built app with a doc
APP="$(find ~/Library/Developer/Xcode/DerivedData -name 'MDPrintView.app' -path '*Debug*' -type d -print -quit)"
open "$APP" docs/plans/2026-06-01-MDPrintView-design.md
```

Tests + smoke:

```sh
xcodebuild -project MDPrintView.xcodeproj -scheme MDPrintView -destination 'platform=macOS' -configuration Debug test
./scripts/smoke.sh
```

## Build system gotchas

- **`project.yml` is the source of truth.** `MDPrintView.xcodeproj` is generated by XcodeGen and tracked alongside; never hand-edit `project.pbxproj` — changes are lost on the next regenerate.
- **Debug builds do NOT have the App Sandbox entitlement.** They use `MDPrintView/MDPrintView-debug.entitlements` (empty plist). On macOS 26, ad-hoc-signed sandboxed apps fail to spawn WKWebView's WebContent helper, leaving the preview pane permanently empty. Release archives (the App Store path via `scripts/archive.sh`) still get the full sandbox — they're signed with the team's distribution identity, which works fine.
- **No network entitlement, ever.** Mermaid + KaTeX are bundled as local JS/CSS. CSP enforces no remote loads.
- **Xcode warnings about unused entitlements file** on first generate are normal — XcodeGen attaches it via the `configs:` build settings per Debug/Release.

## Where the code lives

| Path | Purpose |
|---|---|
| `MDPrintView/Models/` | `MarkdownDocument` (the file), `AppSettings` (persisted preferences), `LayoutMode` |
| `MDPrintView/Rendering/` | `MarkdownRenderer` (swift-markdown → HTML) |
| `MDPrintView/Editor/` | `MarkdownTextView` (NSTextView wrapper), `SyntaxHighlighter`, `LiveFormatStyler` (Hybrid mode), `EditorController`, `EditorToolbar`, `EditorMode`, `MermaidBlock`, `MermaidEditorSheet` |
| `MDPrintView/Preview/` | `PreviewWebView`, `RenderState` (debounced rendering), `PreviewPrintController`, bundled `Resources/preview.{html,css}`, `mermaid.min.js`, `katex.*` |
| `MDPrintView/Views/` | `DocumentView` (composes everything), `OutlineSidebar` |
| `MDPrintView/MDPrintViewApp.swift` | App entry, DocumentGroup, Settings scene, View menu commands |
| `MDPrintViewTests/` | Swift Testing — 50+ tests across renderer, highlighter, styler, controller, outline, MermaidBlock |
| `MDPrintView/PrivacyInfo.xcprivacy` | App Store privacy manifest (no tracking, UserDefaults CA92.1) |
| `MDPrintView/MDPrintView.entitlements` | Release sandbox (App Store) |
| `MDPrintView/MDPrintView-debug.entitlements` | Debug — intentionally empty |
| `scripts/` | `smoke.sh`, `archive.sh`, `generate-icon.swift` |

Deeper architecture detail: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
