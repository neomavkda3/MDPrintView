# Week 4 Notes

## Accessibility — Dynamic Type

macOS does not have automatic Dynamic Type for `NSTextView` the way iOS does. v1 accessibility for editor font scaling is the AppSettings `editorFontSize` slider (Cmd+, → Settings, 10–24pt range). Setting persists via `@AppStorage` and is honored by `SyntaxHighlighter` (via the new `baseFontSize` parameter) and by `MarkdownTextView`'s base font.

Future v1.1+ work: support `NSPreferredFontDescriptor.preferredFont(forTextStyle:)` and live-update on system text-size changes via NSWorkspace notifications. Would require the styler to translate text styles into appropriate heading scales and refresh the text view on `NSAccessibilityNotificationName`.

## Accessibility — VoiceOver

All toolbar buttons have:
- `.help(_:)` — tooltip text on hover
- `.accessibilityLabel(_:)` — explicit VoiceOver pronunciation
- `.accessibilityIdentifier(_:)` — stable string for XCUITest hooks (e.g. `toolbar.bold`, `toolbar.mermaid`)

Outline sidebar rows announce as "Heading: <title>" with the heading level as the VoiceOver hint. The sidebar's List has `.accessibilityIdentifier("sidebar.outline")`.

The editor `NSTextView` inherits its accessibility from AppKit (rotor, item chooser, line/word/paragraph navigation, edit modes). No additional work needed for the editor view itself.

The `WKWebView` preview inherits web accessibility automatically — the rendered HTML's semantic structure (`<h1>`, `<p>`, `<ul>`, etc.) maps to VoiceOver web rotor categories.

Manual VoiceOver smoke test remains pending — requires user with VO enabled to verify pronunciation and navigation feel. Reproducible because the labels are stable strings.

## Accessibility — Color contrast

The app relies on system colors (`textColor`, `linkColor`, `secondaryLabelColor`, `tertiaryLabelColor`, `bar` material) which adapt to light/dark mode and to Increased Contrast accessibility setting automatically. Print mode CSS uses pure black on white (WCAG AAA contrast).

Liquid Glass material (W2.E1) adopts the system's "Reduce Transparency" preference automatically via the SDK — when enabled, the bar above the preview pane becomes more opaque without code changes.

## Accessibility — Keyboard navigation

All toolbar actions have keyboard shortcuts:
- Cmd+B/I/U for bold/italic/strike
- Cmd+1/2/3 for heading levels
- Cmd+K for link insert
- Cmd+Shift+M for Mermaid edit
- Cmd+P / Cmd+Shift+E for print / PDF export
- Cmd+, for Settings

The mode picker (Source/Hybrid) cycles via tab + arrow keys per system convention.
